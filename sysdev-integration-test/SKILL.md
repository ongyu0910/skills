# 結合テスト

**目的**: モジュール同士や外部APIとをつないだとき、基本設計どおりに動くことを確かめる。
**入力**: 基本設計書（結合テスト観点）、単体テストを完了したコード
**成果物**: `docs/07_integration_test/結合テスト仕様書兼結果.md`（自動化した場合はテストコードも）

## 手順

### 1. テストケースの設計

基本設計の「結合テスト観点」を、`IT-001` 形式のケースに展開する。

- **機能間の連携**: 登録 → 一覧に反映 → 編集 → 削除、のようにデータが正しく流れるか。
- **画面遷移**: 画面遷移図のすべての遷移（エラー時の遷移を含む）を、1回以上通す。
- **DBとの結合**: 実際の DB（SQLite など）を使い、制約違反などの振る舞いを確認する。
- **外部APIとの結合**: **本物の API を呼んで**、項目マッピングどおりに画面・DBへ反映されるか確認する。
- **外部APIの異常時**: 実際に発生させにくいものは、次のような方法で再現する。
  - 無効な APIキーを設定する
  - ネットワークを切断する
  - 存在しない ID で問い合わせる

### 2. 実施

- 手動テストでよい。主要なシナリオを E2E ツール（Playwright など）で自動化できれば望ましいが、小規模なら必須ではない。
- 手動で実施した場合は、証跡としてスクリーンショットを `docs/07_integration_test/evidence/` に保存する。
- 外部APIの呼び出し回数を記録し、レート制限・無料枠を超えないよう気をつける。

### 3. 不具合への対応

- NG になったら、原因の工程（設計ミスか、実装ミスか）を特定する。設計ミスなら設計書を修正し、変更管理表に記録する。
- 修正後は、該当ケースと、影響を受けるケースを再テストする（回帰確認）。

## 結合テスト仕様書兼結果テンプレート

```markdown
# 結合テスト仕様書兼結果 v1.0
## 1. 対象・方針・環境（実APIを使用、DB、ブラウザ）
## 2. テストケース
| IT-ID | 観点 | 対象(FN/SCR/API) | 手順 | 期待結果 | 結果 | 実施日 | 証跡 |
|---|---|---|---|---|---|---|---|
## 3. 結果サマリ（件数、OK/NG、不具合件数、API呼び出し回数）
## 4. 不具合一覧（ID / 内容 / 原因工程 / 対応 / 再テスト）
```

## 省略可

- テスト自動化（手動と証跡で代える）
- 正常系で単純な遷移の証跡（NG のケースと主要シナリオの証跡だけでもよい）

## 完了条件（ゲート）

- [ ] 画面遷移図のすべての遷移を実施した
- [ ] すべての API-ID について、本物の API との接続を確認した
- [ ] 外部APIの異常時の振る舞いを、少なくとも1パターン実際に確認した
- [ ] NG がゼロ（または修正済みで、再テストが OK）
- [ ] トレーサビリティ表の IT 列を更新した

## Claude向けメモ

- 手順は、第三者がそのまま再現できる粒度で書く。
- 終わったら `sysdev-system-test` へ進むよう案内する。
